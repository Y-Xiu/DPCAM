# 从原 GitHub 代码迁移到两任务实验代码

本次整理以 `Y-Xiu/DPCAM` 的提交 [`07db8f138a58d3ef519931237ea34a093550a429`](https://github.com/Y-Xiu/DPCAM/commit/07db8f138a58d3ef519931237ea34a093550a429) 为对照，将本地 `trae_experiment` 中的两任务工作流整理为可复现发布版本。仓库历史保留，旧代码可以通过该提交查看。

## 主要变化

| 原仓库入口 / 方式 | 本版入口 / 方式 |
|---|---|
| 根目录 `config.py` 配合 `train.py` | 每个任务与模型的 JSON 配置，加两级训练计划与队列 |
| `process_data1.py`、`splitdata.py` | `prepare_data.py`：由原标注重建掩码，按来源原图划分后裁剪 |
| `test.py`、`test2.py`、独立绘图脚本 | 训练后的检查点验证重载、统一指标报告、全批次完成后的最终测试 |
| 最大验证 IoU 选模，验证指标为 batch 结果的均值 | 最低验证主输出 Dice/Focal 损失选模；整集累积混淆矩阵计算指标 |
| `models/convnext_unet.py`、`models/dpcam.py` | `models/network.py`、`models/attention.py`，结合 `paper_protocol/model.py` 与 `soldef_study/model.py` |
| 单次实验和手动切换注意力 | 九变体 × 两任务 × 五种子的匹配消融计划 |
| 旧说明同时列 SolDef_AI 与 VisA | 当前计划仅执行 SolDef_AI 两个任务 |
| 简单运行环境列表 | 基础环境、现代模型 CUDA 扩展、作者源码固定版本与权重来源分别说明 |
| 图像示例、生成图表等混在源码目录 | 公共仓库保留源码、配置、划分参考和文档；运行产物留在本地 |

旧 `config.py` 的字段默认值为 100 轮、`model_name=unet`、`backbone=resnet50`、`attention_type=cbam`，同时 `use_cbam=False`；这些字段不能等同于所有历史运行中实际构建的网络。本版主模型明确固定为 **ConvNeXt-Base**，采用 150 轮与明确的变体配置。新的工作流将数据清单、配置、运行源码、环境、初始化信息与检查点关联，能够追溯结果属于哪个任务、变体和训练种子。共享参数先初始化、注意力随后添加，减少消融比较中非目标初始化差异。

现代模型采用固定版本作者源码加本地适配。作者仓库与权重通过准备脚本获取，避免将第三方整仓库、编译环境和大型二进制混入主仓库。许可与署名不因本地适配而改变，详见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 兼容边界

这是实验协议和目录结构的迁移，不保证旧 `train.py` 命令或旧权重可以直接用于新配置。即使网络名称相近，也应核对结构、类别顺序、输入尺寸、参数键、数据划分及选模规则后再使用检查点。

旧裁剪级划分曾出现同一来源原图的裁剪跨 train / val / test；新默认协议按来源原图分组。旧结果不能作为当前协议下的一行结果直接填入比较表。旧版百分数口径或把 good 混入 defect recall 的汇总也不能与本版指标混用；本版 F1_macro 保留 0–1，Recall_defect 排除 background 和 good。

`paper_protocol/` 的保留文件作为网络构建与数据加载的共享组件使用，目录名不表示继续执行旧裁剪级实验。新实验入口以 `two_task_study/` 和 `comparison_study/` 为准。

## 已有本地实验的处理

本次发布从独立副本整理；本地原始数据、训练目录、权重、历史报告和论文材料仍保留。公共仓库不携带这些运行产物，也不会依据历史状态文件自动继续训练。

已有实验包含源代码冻结记录。发布过程中对报告、路径或工作流所作的修正，不应直接覆盖旧运行中的快照或修改其哈希来消除报错。恢复旧实验之前，应保全原文件，核对冻结差异并明确哪些结果可以延续，哪些需要建立新批次。

干净复现按照 [README](../README.md) 的准备命令重新生成本机数据清单与配置。准备脚本只针对尚未启动的工作目录；已启动的队列应遵守其冻结和恢复规则。训练任务仍处于暂停状态，当前更新不触发实验续跑。

## 发布验证的范围

源码检查、配置一致性检查、CPU 单元测试与模型结构检查只能证明相应代码路径已检查。它们不能替代 CUDA 扩展的完整输入检查、150 轮训练、检查点验证重载或最终测试。当前实验与验证的实际状态见 [EXPERIMENT_STATUS.md](EXPERIMENT_STATUS.md)，不要将代码发布理解为论文全部结果已完成。
